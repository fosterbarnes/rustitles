v2.4.4 mreCoochie [fix > dark title bar and subtitle matching fixes]

windows:
The title bar is dark as soon as the window opens, instead of only after a minimize. "Show in folder" now opens Explorer on the right file for long and network paths. Adding Python's Scripts folders to PATH no longer breaks existing %VAR% entries or skips a folder whose name is part of another one.

subtitles:
Existing subtitle files next to a video (Name.en.srt) now count as present when more than 1 subtitle per video is set, so they are not downloaded again; with SDH excluded, an .en.sdh.srt does not count as a regular English subtitle. Overwrite backups now include every matching subtitle (.en.srt and .en.sdh.srt), not just the first. Embedded subtitle languages are matched by exact language code, so Estonian (est) no longer counts as Spanish (es). A Subliminal cache error is reported as such instead of "No subtitles found".

settings:
Number boxes (minimum score, subtitles per video, max pages, concurrent downloads) can be cleared and retyped without snapping back to the old value. The OpenSubtitles.com credentials in Subliminal's config are found even with extra spaces or a comment on the header, and on macOS and Linux the settings and Subliminal config files are readable only by you. The update notice also shows on the Linux and macOS dependency install screen.

Under the hood: Linux pipx install refreshes PATH after installing pipx, and version bumps no longer half-apply when the private word list is missing. The pre-push checks passed on Windows (fmt, clippy, tests: 36 passed) and multiBuild built all 8 release files (Windows x64 and ARM64, macOS, Linux). The GUI was not launched, so the dark title bar and the other fixes were not seen running.
